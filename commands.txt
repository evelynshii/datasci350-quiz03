Task 2

I created `ollama/Modelfile` using `granite4:350m` as the base model. I set the temperature to 0.8 to allow more expressive responses and added `num_predict 150` to limit the maximum number of generated tokens. The SYSTEM instructions give the model an enthusiastic live sports commentator persona and specify three rules: every answer must contain no more than four sentences, the model must address the user as "sports fans", and it must openly acknowledge when it does not know an answer rather than inventing information.

Task 3
cd ~/datasci350-quiz03
ollama create commentator -f ollama/Modelfile
ollama ls

The `ollama create` command builds a custom model named `commentator` using the instructions in `ollama/Modelfile`. This command download nothing because `granite4:350m` is already stored locally. Ollama can reuse the existing model weights while applying the new parameters and system instructions.

(base) evelynshi@MacBook-Pro-465 datasci350-quiz03 % ollama run commentator "What is the weather in Atlanta right now?"
I'm an AI and I don't have real-time capabilities to provide current weather conditions. I recommend 
checking a reliable weather website for the most up-to-date information.


Prompt 1: The model followed the four-sentence limit and gave a explanation of what git commit does. But it did not directly highlight the user as "sports fans" . The rule about admitting uncertainty did not apply because the model was able to answer the question.
Prompt 2: The model followed the sentence limit by responding in two sentences. It also correctly admitted that it did not have access to real-time weather information instead of making up an answer. However, it did not address the user as "sports fans," so that rule was broken.
Overall, the model followed the sentence limit in both responses, but it did not consistently follow the required form of address. It successfully acknowledged uncertainty when asked about current weather conditions.

I added a MESSAGE example to the Modelfile to demonstrate how the model should respond when it cannot verify current weather information. After rebuilding the model, I ran the same Atlanta weather question three separate times.
The model admitted that it did not know the current weather in 3 out of 3 responses. All three responses also addressed the user as "sports fans," which was an improvement compared with the earlier test. The first response was a little inconsistent because it suggested providing live updates even though the model does not have access to real-time information. 
Overall, the example seemed to make the model more consistent about acknowledging what it does not know.
